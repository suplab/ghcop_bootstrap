Overview

A seed you fork — and an engine you run

EEIK plays two roles. Most teams start by adopting the configuration into a project; platform teams also run the engine to generate, govern, and keep that configuration current.

🌱

The seed (adopt)

Drop the shared config into any repo with eeik seed --into .. Every AI tool then reads the same golden rules, standards, agents, and memory — so six-to-eight assistants speak one enterprise dialect instead of guessing.

⚙️

The engine (generate + govern)

pip install eeik gives a CLI, a typed SDK, and an MCP server that resolve packs from a manifest, generate tool adapters, and run generation through the HALO confidence gate — audited, staged for human review, never auto-applied.

Posture: EEIK is an engine other tools consume, not a product platform. APEX is the runnable AI-SDLC product and consumes EEIK for onboarding; the SDK/MCP surface is a versioned contract.
Get started

Two ways in

Adopt the config into your project, or run the engine to explore it — no API key, no cloud.

Adopt into a project

# install the engine once pip install -e /path/to/eeik-bootstrap # copy the seed set into this repo eeik seed --into . --apply # check your setup — a fix per issue eeik doctor # then: write project-manifest.yaml, and… eeik activate --apply # materialise the packs you selected eeik generate-adapters --apply # project into all 8 tools

Try the engine

pip install -e ".[test]" # governed generation on the REAL HALO gate eeik demo # query the 25-pack catalog eeik catalog --tag regulated # 7 deployable reference architectures eeik architectures # pin packs + detect drift later eeik lock && eeik diff

Describe the project once

A single project-manifest.yaml captures the stack, domain, governance profile, and delivery model — the source of truth everything else derives from.

Resolve the right intelligence

The engine maps the manifest to capability packs, then materialises their agents and standards into .claude/.

Project into every tool

One generator writes each tool's native format — .github/, .cursor/rules/, .windsurf/rules/, AGENTS.md, and more.

Stay current

eeik lock pins pack versions + content digests; eeik diff flags drift; eeik verify gates conformance in CI.

The governed engine

Generation that can't go rogue

EEIK's generators are agents — and they run on HALO, the same governed runtime APEX uses. Every generation flows through a centralized confidence gate: SUGGEST authority means it can never auto-enforce. Drafts are audited and staged for human review, and it fails safe when HALO is absent.

$ eeik demo EEIK Governed Generation · generator: agent-generator authority SUGGEST action SUGGEST confidence 0.72 gate → auto_enforced: False (G-5: SUGGEST never auto-enforces) bypass counter: 0 (must be 0) → routed to human review reason=suggest sla=14400s ✓ Draft staged for approval: .eeik-staging/agent-generator/artifact.md
🔒

Never auto-applies

auto_enforced is always False and the bypass counter must stay 0 — a consumer can assert both.

📋

Versioned, drift-aware

Packs are dependencies: eeik lock pins versions + digests, eeik diff catches upstream drift.

🔄

Closed loop

eeik lessons turns HALO/APEX audit logs into staged lessons — every project leaves the org smarter.

🧩

Three surfaces, one implementation

CLI, a typed Python SDK (import eeik), and an MCP server all adapt over one API — validate manifests, resolve packs, govern generation, capture lessons.
